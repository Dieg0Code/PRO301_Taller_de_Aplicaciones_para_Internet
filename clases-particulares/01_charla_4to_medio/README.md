- **Caso central:** Landing, marketplace de artistas y sistema de reservas para un studio de tatuajes
- **Duración:** 1 hora

- **Modalidad:** Presencial

# Propósito de la Charla

Esta charla busca mostrar, de forma demostrativa y atractiva, cómo una idea simple de negocio puede transformarse rápidamente en una solución digital usando herramientas actuales de inteligencia artificial, programación web y análisis de datos.

El foco no es hacer una clase técnica exhaustiva, sino ofrecer una experiencia clara, visual y motivadora: partir desde una idea, diseñarla con IA, convertirla en una landing web con catálogo de artistas, capturar reservas simuladas y analizar esos datos en Power BI para tomar decisiones.

La historia completa de la charla es:

```text
idea de negocio
-> diseño con IA
-> landing web
-> catálogo de artistas
-> formulario de reservas
-> datos simulados
-> dashboard en Power BI
-> decisiones de negocio
```

La idea fuerza es que estudiar programación no significa solo escribir código desde cero, sino aprender a crear productos digitales, dirigir herramientas de IA, conectar sistemas y convertir datos en decisiones.

---

# Público Objetivo

La charla está dirigida a estudiantes de 4to medio de un liceo comercial, presumiblemente vinculados al área de programación o especialidades afines.

El contenido debe ser:

- visual y demostrativo;
- fácil de seguir sin experiencia avanzada;
- suficientemente moderno para generar interés;
- conectado con negocios, tecnología y datos;
- orientado a mostrar posibilidades reales de estudio y trabajo en programación.

No se busca profundizar en teoría de IA, arquitectura de software ni modelamiento de datos. El objetivo es que los estudiantes vean una cadena completa de creación digital y entiendan que programación puede conectar creatividad, automatización, diseño, datos y decisiones.

# BLOQUE 1: De una idea de negocio a una experiencia digital

- **Duración estimada:** 10 minutos
- **Objetivo del bloque:** activar el interés de los estudiantes mostrando que una idea cotidiana puede convertirse rápidamente en una solución digital cuando se combinan IA, programación web y datos.
- **Intención comunicacional:** instalar un primer momento de curiosidad: “esto no es una charla abstracta de tecnología; vamos a construir algo que podría usar un negocio real”.

## Punto de partida

La charla comienza con una idea simple:

> Imaginemos que queremos lanzar un studio de tatuajes y necesitamos presencia digital hoy, no en tres meses.

El negocio necesita resolver varias cosas al mismo tiempo:

- mostrar estilo visual y personalidad;
- enseñar trabajos, servicios o tipos de tatuajes;
- recibir solicitudes de reserva;
- ordenar datos de posibles clientes;
- entender qué estilos se piden más;
- detectar días u horarios con más demanda;
- y tomar decisiones con información, no solo con intuición.

Antes, para prototipar algo así se necesitaban varias etapas separadas:

```text
idea
-> diseñador
-> programador
-> formulario
-> planilla
-> análisis manual
-> reporte
```

Hoy, con herramientas de IA y plataformas de datos, ese ciclo se puede demostrar de forma mucho más rápida:

```text
idea
-> diseño con IA
-> landing programada
-> reservas simuladas
-> dashboard en Power BI
-> decisiones de negocio
```

La idea no es prometer que todo queda perfecto automáticamente. La idea para esta charla es más directa y atractiva:

> Si sabes dirigir herramientas digitales, puedes convertir una idea en algo visible, funcional y medible en muy poco tiempo.

## Caso central: studio de tatuajes

El caso de la charla será un studio de tatuajes ficticio.

La elección del caso funciona bien porque mezcla:

- estética visual fuerte;
- identidad de marca;
- público joven;
- reserva de horas;
- preferencias personales;
- datos fáciles de imaginar;
- y decisiones comerciales simples.

Ejemplo de concepto:

```text
Nombre tentativo:
Ink Pulse Studio

Tipo de negocio:
Studio de tatuajes moderno, visual, urbano y orientado a reservas online.

Necesidad:
Crear una landing atractiva con catálogo de artistas y formulario para que las personas puedan solicitar una hora eligiendo con quién quieren tatuarse.
```

El formulario de reservas puede capturar datos como:

- nombre;
- contacto;
- artista preferido;
- estilo de tatuaje;
- zona del cuerpo;
- tamaño aproximado;
- presupuesto estimado;
- fecha tentativa;
- horario preferido;
- estado de la solicitud.

Esos datos luego permitirán construir preguntas de negocio:

- ¿qué estilos de tatuaje se piden más?
- ¿qué artistas reciben más solicitudes?
- ¿cuál es el presupuesto promedio?
- ¿qué días concentran más reservas?
- ¿qué zonas del cuerpo aparecen más?
- ¿cuántas solicitudes están pendientes o confirmadas?
- ¿qué tipo de cliente parece más frecuente?

Así, la landing deja de ser solo una página bonita. Se convierte en una puerta de entrada a un marketplace de artistas, a reservas y a datos que luego pueden analizarse.

## Mensaje para los estudiantes

En este bloque conviene hablarles de forma directa:

> Programar no es solo escribir líneas raras en una pantalla negra. Programar también puede ser crear una experiencia, conectar herramientas, automatizar tareas y transformar datos en decisiones.

La charla debe mostrar que el perfil técnico moderno puede moverse entre varias capas:

```text
diseño
-> web
-> formulario
-> datos
-> dashboard
-> decisión
```

Ese recorrido es importante para captar interés, porque muestra una versión más atractiva y actual de la programación:

- no solo código;
- no solo teoría;
- no solo matemáticas;
- no solo “hacer páginas”;
- sino crear soluciones completas con apoyo de herramientas modernas.

## Mini guion sugerido

Una posible forma de abrir:

```text
Hoy no quiero partir explicando IA con una definición larga.

Quiero partir con una pregunta:

¿Qué pasaría si tuviéramos que lanzar mañana la presencia digital de un studio de tatuajes?

Necesitamos una idea visual, una página, un formulario, datos de reservas y una forma de entender qué está pasando con ese negocio.

La gracia es que hoy podemos prototipar todo ese recorrido usando IA, programación y Power BI.
```

Luego se presenta la promesa:

```text
En esta hora vamos a mirar el recorrido completo:

primero imaginamos el negocio,
después diseñamos una landing con IA,
luego la convertimos en una web,
generamos datos de reservas
y finalmente los analizamos en Power BI.
```

## Resultado esperado del bloque

Al terminar este bloque, los estudiantes deberían tener claro:

- cuál es el caso que se va a construir;
- por qué una landing puede ser útil para un negocio;
- qué datos puede producir un formulario;
- y por qué combinar IA, programación y Power BI puede ser atractivo para crear soluciones reales.

La transición natural al siguiente bloque es:

> Ya tenemos la idea del negocio. Ahora vamos a pedirle a una IA de diseño que nos ayude a imaginar cómo podría verse esa landing.

# BLOQUE 2: Diseño de la landing con IA

- **Duración estimada:** 12 minutos
- **Objetivo del bloque:** mostrar cómo una herramienta de IA puede transformar una idea inicial en una propuesta visual concreta para una landing page.
- **Intención comunicacional:** generar el primer momento “wow” de la charla: una idea descrita en lenguaje natural comienza a convertirse en una interfaz visual atractiva.

## Propósito del bloque

Este bloque debe mostrar que la IA no solo responde preguntas. También puede ayudar a crear primeras versiones de productos visuales.

La idea es que los estudiantes vean una transformación rápida:

```text
descripción del negocio
-> prompt de diseño
-> propuesta visual
-> secciones de landing
-> identidad inicial del proyecto
```

Para el público de 4to medio, este momento debe sentirse más cercano a una demostración creativa que a una explicación técnica. Lo importante es que vean que una idea puede tomar forma visual en pocos minutos.

## Herramienta sugerida

La herramienta principal para este bloque será **Stitch** u otra herramienta de diseño asistido por IA equivalente.

El foco no estará en explicar todas sus opciones, sino en mostrar el flujo:

1. se describe el negocio;
2. se pide una landing;
3. se define una estética;
4. se revisa la propuesta visual;
5. se identifican las partes que luego podrían programarse.

## Qué debe tener la landing

La landing del studio de tatuajes debería incluir secciones simples y reconocibles:

- hero principal con nombre del studio;
- bajada breve de propuesta de valor;
- botón de reserva;
- sección de estilos de tatuaje;
- muestra visual o galería;
- beneficios o razones para reservar;
- formulario de solicitud de hora;
- sección de contacto o ubicación;
- llamada final a reservar.

No hace falta que la landing sea perfecta. En una charla de captación, lo importante es que se vea suficientemente real como para que los estudiantes piensen:

> Esto podría ser una página de verdad.

## Prompt sugerido para Stitch

Un prompt posible para generar la primera propuesta:

```text
Diseña una landing page moderna, visual y atractiva para un studio de tatuajes llamado Ink Pulse Studio.

El sitio debe tener una estética urbana, elegante y premium, orientada a jóvenes y adultos que quieren reservar una hora para tatuarse.

Incluye:
- un hero impactante con nombre del studio;
- una frase principal breve;
- botón claro para reservar hora;
- sección de estilos de tatuaje: fine line, blackwork, tradicional, minimalista y lettering;
- una galería visual de trabajos;
- una sección que explique por qué elegir el studio;
- un formulario de reserva con nombre, contacto, estilo, zona del cuerpo, tamaño, presupuesto y fecha tentativa;
- una sección final de contacto.

Quiero un diseño con alto contraste, buena jerarquía visual, tipografía fuerte, imágenes grandes, cards elegantes y una experiencia que se sienta profesional, no genérica.
```

Si se quiere reforzar el efecto marketing, se puede usar una versión más ambiciosa:

```text
Crea una landing page con estética de marca premium para un studio de tatuajes moderno.

Debe sentirse como el sitio de un negocio real que quiere captar reservas online.

La primera pantalla debe impactar visualmente.
El formulario debe verse simple, confiable y fácil de completar.
El diseño debe transmitir estilo, confianza, arte y experiencia.
```

## Qué mostrar mientras aparece el diseño

Mientras la herramienta genera la propuesta visual, conviene explicar brevemente:

- la IA está interpretando una descripción en lenguaje natural;
- no estamos partiendo desde una pantalla vacía;
- el resultado sirve como primer prototipo;
- después se puede modificar, programar o adaptar;
- una persona con criterio decide qué mantener y qué cambiar.

Pero el tono principal debe seguir siendo aspiracional:

> Antes necesitábamos partir desde cero. Ahora podemos partir desde una idea mucho más avanzada y mejorarla.

## Lectura rápida de la propuesta visual

Cuando aparezca el diseño, conviene revisar con los estudiantes:

### 1. Primera impresión

Preguntar:

```text
¿Esto se siente como un negocio real?
¿Llama la atención?
¿Dan ganas de seguir bajando?
```

La idea es mostrar que el diseño no es solo decoración. La primera impresión puede influir en si una persona confía, reserva o se va.

### 2. Jerarquía visual

Observar:

- qué se ve primero;
- dónde está el botón de reserva;
- si el nombre del studio se entiende;
- si las secciones están ordenadas;
- si el formulario parece fácil de completar.

### 3. Conversión

Introducir una palabra simple pero potente:

> Conversión significa que una persona hace la acción que queremos: reservar, escribir, comprar, registrarse o pedir información.

En esta landing, la conversión principal es:

```text
visita
-> interés
-> formulario de reserva
```

Esto conecta directamente con el siguiente bloque, donde la landing deja de ser solo visual y pasa a convertirse en una página programada.

## Qué partes se pueden convertir en código

Después de mostrar el diseño, se puede explicar que una landing visual normalmente se transforma en piezas programables:

```text
hero
-> sección HTML/CSS

cards de estilos
-> componentes visuales

galería
-> grid de imágenes

formulario
-> campos de entrada

botón reservar
-> acción o envío de datos
```

Este punto es importante porque empieza a conectar diseño con programación sin volver la charla demasiado técnica.

La idea es que los estudiantes entiendan:

- la IA puede ayudar a imaginar;
- el diseño puede guiar la programación;
- el formulario puede producir datos;
- y esos datos luego pueden analizarse.

## Mini guion sugerido

Una posible explicación:

```text
Ya tenemos una idea: un studio de tatuajes que quiere recibir reservas.

Ahora vamos a hacer algo interesante: en vez de abrir una hoja en blanco, vamos a describirle el negocio a una IA de diseño.

Le vamos a pedir que imagine una landing completa: portada, estilos, galería y formulario.

Esto no es todavía la página final, pero sí es un prototipo visual. Es una forma rápida de pasar desde “tengo una idea” a “ya puedo ver cómo podría funcionar”.
```

Cuando aparezca el resultado:

```text
Aquí ya podemos discutir como si fuera un proyecto real:

¿se entiende el negocio?
¿hay un botón claro?
¿el formulario tiene sentido?
¿qué datos podríamos guardar?
¿qué podríamos mejorar antes de programarlo?
```

## Resultado esperado del bloque

Al terminar este bloque, los estudiantes deberían haber visto:

- cómo una descripción se transforma en interfaz;
- cómo la IA puede acelerar la etapa visual de un proyecto;
- qué secciones necesita una landing orientada a reservas;
- qué significa pensar una página desde conversión;
- y cómo un diseño puede convertirse en punto de partida para programar.

La transición natural al siguiente bloque es:

> Ya tenemos una propuesta visual. Ahora viene la parte más interesante para programación: convertir esa idea en una web real con formulario.

# BLOQUE 3: Construcción de la web y formulario con apoyo de IA

- **Duración estimada:** 15 minutos
- **Objetivo del bloque:** mostrar cómo una propuesta visual puede convertirse en una landing web funcional con formulario de reservas usando programación asistida por IA.
- **Intención comunicacional:** generar el segundo momento “wow”: la idea ya no solo se ve como diseño, ahora empieza a existir como una página web real.

## Propósito del bloque

Este bloque debe mostrar la parte más cercana a la programación, pero sin convertir la charla en una clase larga de HTML, CSS o JavaScript.

La idea es transmitir:

```text
la IA ayuda a acelerar
la programación convierte la idea en producto
el formulario transforma visitas en datos
```

Para estudiantes de 4to medio, el objetivo no es que entiendan cada línea de código en ese momento. El objetivo es que vean que programar permite tomar una maqueta visual y convertirla en algo interactivo.

## Enfoque recomendado para la demo

La demo puede mostrarse de dos maneras:

1. **Versión en vivo:** pedirle a Codex que genere o adapte la landing durante la charla.
2. **Versión preparada:** tener la landing lista y mostrar brevemente cómo se construyó con ayuda de IA.

Para una charla de captación, conviene tener una versión preparada para evitar riesgos técnicos, pero hacer una pequeña intervención en vivo para que se vea la magia.

Ejemplo:

- mostrar la landing ya lista;
- pedir un cambio visible en vivo, como modificar el texto principal, agregar un campo al formulario o cambiar una sección;
- regenerar o ajustar rápido;
- recargar la página;
- mostrar que el cambio aparece.

Eso mantiene control y al mismo tiempo genera efecto demostrativo.

## Qué se construye

La landing debe representar el studio de tatuajes definido en los bloques anteriores.

Estructura sugerida:

```text
landing/
├── index.html
├── styles.css
└── script.js
```

O, si se quiere usar una versión más moderna:

```text
landing/
├── src/
│   ├── App.jsx
│   ├── main.jsx
│   └── styles.css
└── package.json
```

Para esta charla, la opción más conveniente probablemente sea una landing simple en HTML, CSS y JavaScript, porque permite abrirla rápido, explicar visualmente y evitar setup innecesario.

La página debería incluir:

1. **Hero principal**
   - nombre del studio;
   - frase llamativa;
   - botón para reservar;
   - imagen o fondo visual potente.

2. **Estilos de tatuaje**

## El formulario como punto clave

El formulario es la parte más importante del bloque porque conecta la web con los datos.

La página no debe verse solo como una vitrina bonita. Debe mostrar que una web puede capturar información útil.

Ejemplo de campos:

```text
Nombre
Instagram o WhatsApp
Estilo de tatuaje
Zona del cuerpo
Tamaño aproximado
Presupuesto estimado
Fecha tentativa
Horario preferido
Mensaje adicional
```

Cada campo tiene sentido para el negocio:

- el estilo ayuda a saber qué se está pidiendo;
- la zona del cuerpo orienta la complejidad;
- el tamaño influye en tiempo y precio;
- el presupuesto permite segmentar clientes;
- la fecha ayuda a organizar agenda;
- el contacto permite cerrar la reserva.

Aquí se puede instalar una idea muy potente:

> Cada formulario es una conversación entre el negocio y sus futuros datos.

## Prompt sugerido para construir con Codex

Un prompt posible para la demo:

```text
Crea una landing page estática en HTML, CSS y JavaScript para un studio de tatuajes llamado Ink Pulse Studio.

Debe verse moderna, visual, urbana y profesional.
```

```text
"Solicitud recibida. El equipo revisará tu idea y te contactará para coordinar la hora."
```

Este segundo tipo de prompt es ideal para mostrar intervención en vivo sin arriesgar toda la construcción.

## Qué explicar mientras se muestra el código

No conviene explicar línea por línea. En una charla de una hora, eso puede bajar la energía.

Es mejor mostrar capas:

```text
HTML -> estructura
CSS -> apariencia
JavaScript -> interacción
```

Explicación breve:

- HTML define qué elementos existen: títulos, secciones, botones, formulario.
- CSS define cómo se ven: colores, tamaños, posiciones, cards, responsive.
- JavaScript permite interacción: validar, responder al envío, simular datos.

La explicación puede ser:

> No necesitan entender cada línea ahora. Lo importante es ver que una página web está hecha de piezas. La IA puede ayudar a generar una primera versión, pero la programación es lo que permite ordenar esas piezas, conectarlas y hacerlas funcionar.

## Momento demostrativo sugerido

El bloque puede tener esta secuencia:

```text
1. Mostrar la landing funcionando.
2. Hacer scroll rápido por las secciones.
3. Llegar al formulario.
4. Completar una reserva ficticia.
5. Enviar el formulario.
6. Mostrar mensaje de confirmación.
7. Explicar que esos campos pueden transformarse en datos.
```

Ejemplo de reserva ficticia:

```text
Nombre: Valentina
Contacto: @vale.ink
Estilo: fine line
Zona: brazo
Tamaño: mediano
Presupuesto: 80000
Fecha tentativa: viernes
Horario: tarde
```

Después de enviar:

```text
Solicitud recibida. El equipo revisará tu idea y te contactará para coordinar la hora.
```

Ese pequeño momento permite conectar emocionalmente:

> Esto ya parece una reserva real.

## De formulario a datos

La transición más importante del bloque es explicar que cada envío de formulario puede convertirse en una fila de datos.

Ejemplo:

```text
nombre | estilo | zona | tamaño | presupuesto | fecha | horario | estado
Valentina | fine line | brazo | mediano | 80000 | viernes | tarde | pendiente
```

Ahí se prepara el siguiente bloque:

> Si recibimos una reserva, tenemos una fila. Si recibimos cien reservas, tenemos patrones. Y si tenemos patrones, podemos tomar decisiones.

Esto abre la puerta a Power BI.

## Qué vender de la programación en este bloque

El mensaje de marketing debe ser claro:

> La programación convierte ideas en experiencias reales.

Y también:

> La IA puede ayudar a ir más rápido, pero alguien debe saber qué pedir, cómo ordenar el resultado y cómo convertirlo en algo que funcione.

No es necesario insistir demasiado en límites o advertencias. En este contexto, interesa mostrar capacidad y posibilidad:

- puedes construir una página;
- puedes hacerla interactiva;
- puedes capturar datos;
- puedes conectar eso con análisis;
- puedes crear algo que un negocio podría usar.

## Mini guion sugerido

Una posible explicación:

```text
Hasta ahora teníamos una idea y una propuesta visual.

Pero una imagen no recibe reservas.
Una imagen no guarda datos.
Una imagen no se puede analizar en Power BI.

Por eso necesitamos convertir el diseño en una página web.
```

Luego:

```text
Aquí entra la programación.

La IA puede ayudarnos a generar una primera versión del código, pero lo importante es que ahora tenemos estructura, estilos e interacción.

Esta landing ya tiene secciones, botón de reserva y un formulario.
```

Al completar el formulario:

# BLOQUE 4: De reservas a decisiones con Power BI

- **Duración estimada:** 18 minutos
- **Objetivo del bloque:** mostrar cómo los datos generados por una web pueden transformarse en un dashboard visual para entender el comportamiento de un negocio.
- **Intención comunicacional:** cerrar el recorrido con un tercer momento “wow”: la página ya no solo recibe reservas, ahora produce información que ayuda a tomar decisiones.

## Propósito del bloque

Este bloque muestra la parte de datos de la charla.

La idea es que los estudiantes vean que un formulario no termina cuando alguien presiona el botón de enviar. Cada respuesta puede convertirse en una fila de datos y muchas filas juntas pueden revelar patrones.

El recorrido del bloque es:

```text
reservas del formulario
-> tabla de datos
-> limpieza o revisión simple
-> dashboard en Power BI
-> preguntas de negocio
-> decisiones
```

El mensaje principal es:

> Una web captura datos. Power BI ayuda a convertir esos datos en una historia visual para decidir mejor.

## Datos simulados para la demo

Para que la demostración funcione bien en una charla de una hora, conviene llevar un archivo preparado con reservas ficticias.

El archivo puede estar en formato `.csv` o `.xlsx` y representar muchas solicitudes de reserva recibidas por la landing.

Columnas sugeridas:

```text
id_reserva
fecha_solicitud
nombre_cliente
contacto
estilo_tatuaje
zona_cuerpo
tamanio
presupuesto_estimado
fecha_tentativa
horario_preferido
estado_solicitud
artista_sugerido
fuente_contacto
```

Ejemplo de fila:

```text
001 | 2026-05-13 | Valentina Rojas | @vale.ink | fine line | brazo | mediano | 80000 | 2026-05-20 | tarde | pendiente | Camila | Instagram
```

La tabla no necesita ser compleja. Debe ser suficientemente realista para que los estudiantes entiendan que esos datos podrían venir de clientes reales.

El dataset puede tener entre 60 y 100 reservas ficticias. Eso permite que el dashboard muestre patrones sin volverse pesado.

## Prompt sugerido para generar datos ficticios

Un prompt útil para preparar el archivo antes de la charla:

```text
Genera 80 reservas ficticias para un studio de tatuajes llamado Ink Pulse Studio.

Entrégalas en formato CSV.

Columnas:
- id_reserva

```

Este prompt sirve para mostrar otra idea potente de IA:

> La IA también puede ayudar a crear datos de prueba para practicar, prototipar y demostrar una solución.

## Preguntas de negocio

Antes de abrir Power BI, conviene instalar una idea simple:

> No usamos datos solo para tener gráficos bonitos. Usamos datos para responder preguntas.

Preguntas que el dashboard puede responder:

- ¿cuántas reservas se recibieron?
- ¿cuál es el presupuesto promedio?
- ¿qué estilo de tatuaje se solicita más?
- ¿qué zonas del cuerpo aparecen con mayor frecuencia?
- ¿cuántas solicitudes están pendientes, confirmadas o canceladas?
- ¿qué fuente trae más interesados: Instagram, TikTok, Google o recomendaciones?
- ¿en qué horarios se concentra más la demanda?
- ¿qué artista podría tener mayor carga de trabajo?

Estas preguntas ayudan a que Power BI no se vea como una herramienta aislada, sino como una forma de mirar el negocio.

## Dashboard sugerido en Power BI

El dashboard debe ser simple, visual y fácil de leer.

Elementos recomendados:

1. **Tarjeta de total de reservas**
   - muestra cuántas solicitudes se recibieron.

2. **Tarjeta de presupuesto promedio**
   - muestra el valor promedio estimado por solicitud.

3. **Tarjeta de reservas confirmadas**
   - muestra cuántas solicitudes ya tienen mayor probabilidad de convertirse en venta.

4. **Gráfico de barras por estilo de tatuaje**
   - permite identificar qué estilos generan más interés.

5. **Gráfico de dona por estado de solicitud**
   - permite ver pendientes, confirmadas, reagendadas y canceladas.

6. **Gráfico por fuente de contacto**
   - permite reconocer si Instagram, TikTok, Google o recomendaciones están trayendo más gente.

7. **Gráfico por horario preferido**
   - permite entender si la demanda se concentra en mañana, tarde o noche.

8. **Segmentadores**
   - filtro por estilo;
   - filtro por estado;
   - filtro por fuente de contacto.

Con eso basta para que el dashboard se vea como una herramienta real de gestión.

## Secuencia de demostración en Power BI

La demostración puede seguir esta secuencia:


No es necesario construir todo el dashboard desde cero en vivo. Para mantener ritmo, conviene llevarlo preparado y hacer una pequeña acción visible durante la charla:

- cambiar un filtro;
- crear una tarjeta simple;
- ordenar un gráfico;
- seleccionar un estilo de tatuaje;
- o mostrar cómo cambia todo el tablero al hacer clic.

La parte importante es que se vea la relación:

```text

-> datos

-> decisión
```

## Decisiones que podría tomar el negocio

Luego de ver el dashboard, se pueden plantear decisiones simples:

- si `fine line` es el estilo más solicitado, conviene destacarlo más en la landing;
- si Instagram trae más reservas, conviene invertir más contenido ahí;
- si muchas solicitudes quedan pendientes, se necesita mejorar el seguimiento;
- si el horario de tarde concentra demanda, se puede ajustar la agenda;
- si los presupuestos altos vienen de ciertos estilos, se pueden crear paquetes especiales;
- si un artista aparece demasiado asignado, se puede redistribuir la carga.

Este punto es clave para que Power BI no se vea solo como una herramienta de oficina.

Debe verse como una herramienta para responder:

```text
qué está pasando
por qué importa
qué podríamos hacer ahora
```
